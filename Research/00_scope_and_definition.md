# L0 的定义、研究边界与证据标准

## 1. 项目定义

本项目中的 L0 是一个**交付级别**，不是一条单独 loss，也不是论文中通用的训练阶段名：

> L0 = 建立一个完整、可复现、可评测的 VLM 能力生产流程，使模型在预先声明的参数、数据、训练和推理预算下，达到同档公开前沿模型的综合能力水平。

因此，L0 同时包含：

- 架构与视觉 token 设计；
- 视觉、语言和多模态数据系统；
- 预训练/继续预训练与长上下文扩展；
- 指令、推理、偏好、强化学习和工具使用后训练；
- 污染控制、反事实视觉依赖测试、文本回归和推理效率；
- checkpoint、配方、数据谱系、评测证据和迭代闭环。

## 2. 与业界术语的冲突

多个 VLM 项目把初始桥接阶段称为 Stage 0：冻结视觉编码器和语言模型，只训练 projector/MLP/Q-Former，使视觉特征落入 LLM embedding 空间。这个阶段有价值，但能力上限受两个冻结骨干限制，无法代表完整的 SOTA 训练。

项目应采用下面的命名纪律：

| 名称 | 含义 | 是否等同项目 L0 |
|---|---|---:|
| L0 | 完整能力交付级别 | 是 |
| P0–P10 | L0 内部阶段 | 否，合起来才是 L0 |
| Connector warm-up / P2 | 冻结骨干训练连接层 | 否 |
| SFT / RL | 后训练阶段 | 否，但通常是 L0 必需组成 |

所以，你对 L0 的定义没有逻辑问题；它只是项目私有 taxonomy。真正要避免的是在工程文档中只写“Stage 0/L0”而不声明语义。

## 3. “匹配 SOTA”必须先限定比较条件

公开榜单上的绝对第一不是一个稳定目标。较严谨的表述是：

> 在相同或相近的 active parameter、视觉 token、上下文长度、测试时采样/工具预算和公开数据约束下，进入目标能力集合的 Pareto 前沿，并且没有不可接受的文本能力或效率退化。

至少固定五个边界：

1. **模型档位**：总参数、激活参数、ViT 参数、是否 MoE。
2. **训练预算**：总 token、图像/视频量、分辨率、训练 FLOPs、教师推理预算。
3. **推理预算**：视觉 token、CoT token、采样次数、工具调用和外部 OCR/搜索。
4. **数据制度**：公开/私有、合成数据、教师来源、测试集防污染截止时间。
5. **能力集合**：通用 VQA 还是文档、视频、推理、GUI、grounding 的综合目标。

若这些边界未声明，只能说“在若干榜单有竞争力”，不能说“匹配 SOTA”。

## 4. 三种总路线

### A. 冻结骨干、只训桥接层

优点是便宜、稳定、适合检查接口；缺点是不能让 ViT 适配 OCR/grounding，也不能让 LLM 深层形成视觉推理。它是 baseline 或 P2，不应作为最终路线。

### B. 预训练骨干 + 全参数联合继续预训练

先使用强 ViT 和强 LLM，经过短桥接热身后，逐步或直接解冻全部组件，在图文、纯文本、视频和专项数据上联合训练。这是当前公开前沿模型中最常见、也最可迁移的路线。Qwen3-VL、Kimi-VL、InternVL3.5、Molmo2 的公开报告虽细节不同，都把大规模联合训练和完整后训练放在主线上：[Qwen3-VL](https://arxiv.org/abs/2511.21631)、[Kimi-VL](https://arxiv.org/abs/2504.07491)、[InternVL3.5](https://arxiv.org/abs/2508.18265)、[Molmo2](https://arxiv.org/abs/2601.10611)。

### C. 原生早期图文联合预训练

在语言预训练早期就持续加入中等比例视觉数据，使多模态能力成为基础模型本体的一部分。Kimi K2.5 报告在固定 token 预算下，“早期较低视觉比例”优于“后期突然加入高比例视觉”的策略：[Kimi K2.5](https://arxiv.org/abs/2602.02276)。

这是值得追踪的前沿方向，但其证据来自超大规模训练，不能不经验证地外推到小模型或预算有限的 post-hoc adaptation。

## 5. 当前研究边界

本轮只回答方法问题：什么能力必须建、各阶段为何存在、公开证据支持什么、有哪些风险和消融。当前明确不做：

- 不选择具体 ViT/LLM checkpoint；
- 不给单张本地显卡设计“全量训练”方案；
- 不编写训练代码或修改框架；
- 不承诺没有计算预算定义的 SOTA 结果；
- 不把论文中未披露的超参数臆测为标准配方。

## 6. 证据等级

| 等级 | 定义 | 可支持的结论 |
|---|---|---|
| E1 | 官方技术报告明确披露，且有规模/阶段/评测信息 | “该项目做过什么” |
| E2 | 多个独立项目的 E1 事实趋同 | “目前的共同模式” |
| E3 | 受控消融或固定预算对比 | “某设计在该条件下更好” |
| E4 | 本研究的跨项目综合 | “推荐优先验证的假设” |
| E5 | 未公开、不可复现或仅营销陈述 | 只能列为未知，不能用于定论 |

这里特别区分“成功项目采用了 X”和“X 导致成功”。前者是相关性事实；只有严格消融才能接近因果结论。
