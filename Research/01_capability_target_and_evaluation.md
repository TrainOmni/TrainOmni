# SOTA 能力目标与评测体系

## 1. 为什么先做能力契约

VLM 的“能力”至少有十个互相牵制的维度。只追一个聚合榜单，模型可能通过语言先验、训练集污染、更长 CoT 或更大视觉 token 预算获得高分，却没有真正变得更会看。

推荐在任何数据和训练配方之前，先写一份 machine-readable 的 capability contract：每个能力的目标、对标模型、测试集、污染规则、推理预算、最低门槛和不可退化项。

## 2. 能力树

| 能力域 | 要验证什么 | 典型公开测试方向 | 必须增加的内部测试 |
|---|---|---|---|
| 基础感知 | 物体、属性、场景、细粒度识别 | 通用 VQA/MMStar | 长尾属性、图像扰动 |
| OCR/文档/图表 | 小字、布局、表格、公式、图表关系 | DocVQA、ChartQA、OCRBench | 私有扫描件、低清/旋转/多页 |
| 知识与 STEM 推理 | 视觉证据参与多步推理 | MMMU-Pro、MathVista 类 | 新生成题、过程可核验题 |
| 空间/计数/grounding | 坐标、指代、相对位置、数量 | RefCOCO、counting 类 | 反事实位置交换、密集小物体 |
| 多图与视频 | 跨图比较、时间、事件和长视频 | Video-MME、MLVU 类 | 时间戳扰动、帧删除、镜头重排 |
| 指令与对话 | 遵循格式、拒答、连续视觉对话 | 多模态 chat/human eval | 多轮状态、含糊指令澄清 |
| 幻觉与视觉依赖 | 答案是否来自图像而非语言猜测 | HallusionBench/MMHal 类 | 空白图、错图、shuffle 图 |
| GUI/工具/Agent | 定位控件、规划、调用工具、读取反馈 | ScreenSpot/GUI 类 | 沙盒任务成功率、非法动作率 |
| 文本保持 | 语言、代码、数学是否因多模态训练退化 | 对应文本基准 | 与原始 LLM 的成对回归集 |
| 效率 | 每个能力花多少视觉/思维 token 和时延 | 吞吐、显存、首 token 时延 | 能力-成本 Pareto 曲线 |

公开套件可用 [VLMEvalKit](https://arxiv.org/abs/2407.11691) 和 [lmms-eval](https://arxiv.org/abs/2407.12772) 统一运行，但统一 runner 不等于统一可信度，仍需检查 prompt、版本、图像预处理和 answer extraction。

## 3. 必做的反事实视觉依赖测试

### 3.1 四路输入对照

对同一道题至少运行：

1. 正确图像 + 问题；
2. 无图/空白图 + 问题；
3. 随机错图 + 问题；
4. 正确图像但局部遮挡/打乱 + 问题。

报告绝对准确率之外，还要报告 `正确图 - 无图`、`正确图 - 错图` 的增益。若去掉图像几乎不降，模型可能只是在利用文本先验。

[MMStar](https://arxiv.org/abs/2403.20330) 和 [MMMU-Pro](https://arxiv.org/abs/2409.02813) 都把“文本模型也能答”的样本筛除问题放到了评测设计中心，这证明视觉依赖不是附加项，而是当前公开评测的核心缺口。

### 3.2 输出可归因性

对 grounding、OCR、计数、时序问题，优先使用可自动核验的证据：框/点、文本 span、时间区间、公式或结构化中间结果。只让模型生成漂亮解释并不能证明它依据了图像。

## 4. 污染控制

评测数据要经过至少四层检查：

- 图像近重复：感知哈希、embedding ANN、裁剪/水印鲁棒匹配；
- 文本近重复：规范化 question/answer、MinHash/语义检索；
- 图文联合重复：同图异问和同问异图都要检查；
- 教师污染：合成数据教师是否见过测试集，无法确认时单独标记。

Idefics3 的研究对 MathVista 进行了污染审计，并报告了训练来源与评测图像/问答的重叠风险；这类结果意味着“只删除完全相同文本”远远不够：[Idefics3](https://arxiv.org/abs/2408.12637)。

建议把最终证明分成三层：

- 公开标准集：便于横向比较；
- 截止日后的私有/动态集：降低泄漏；
- 人类或环境成功率：验证开放式质量与 Agent 行为。

## 5. 公平预算协议

对每个结果同时记录：

- 图像缩放/切片、帧数和视觉 token 数；
- 最大上下文和实际输入/输出 token；
- greedy、采样、self-consistency 次数；
- 是否启用 CoT、OCR、代码执行、裁剪/缩放、搜索；
- 模型 active parameters、精度、batch 和硬件；
- 单样本时延、峰值显存、吞吐和失败重试。

若基线不用工具而候选模型用了工具，应分别报告 **base VLM** 与 **agentic system** 两张表。

## 6. 阶段门禁，而不是最终一次总评

| 门禁 | 核心问题 | 失败时回到哪里 |
|---|---|---|
| G0 数据/评测 | 评测是否去重、可重复、可归因 | P0 数据治理 |
| G1 视觉编码 | OCR、细粒度、位置表征是否够用 | P1 ViT/分辨率/token 化 |
| G2 模态接入 | 图像 token 是否稳定影响输出 | P2/P3 接入与联合训练 |
| G3 联合预训练 | 能力增长且文本回归可控吗 | P3 数据混合/学习率 |
| G4 长上下文 | 多图/视频增长是否以其他能力为代价 | P5 curriculum/采样 |
| G5 SFT | 指令、格式、拒答和通用性是否平衡 | P6 数据/损失权重 |
| G6 推理/RL | 真实准确率提高还是长度/奖励投机 | P7–P9 reward 与难度 |
| G7 交付 | 能力-成本是否进入目标 Pareto 面 | P10 压缩或全流程回滚 |

## 7. SOTA 声明的最低证据包

只有同时具备以下材料，才建议使用“匹配同档 SOTA”的表述：

1. 至少一个多域公开评测矩阵，而非单榜单；
2. 与同档强基线使用相同推理预算；
3. 无图/错图/遮挡反事实结果；
4. 图像与文本污染审计；
5. 原始 LLM 文本能力回归；
6. 至少三次关键阶段复现或给出不确定区间；
7. 参数、token、FLOPs、数据类别和后训练方法的透明记录；
8. 延迟、视觉 token 和显存成本。

否则更准确的措辞是“在指定 benchmark 上达到竞争性结果”。
