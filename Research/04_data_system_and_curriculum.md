# 数据系统、混合策略与课程学习

## 1. 数据不是一个列表，而是一套生产系统

SOTA 级 VLM 数据系统至少有五层：

```text
来源与许可
  → 下载/解析/去重/安全清洗
  → caption、OCR、grounding、QA 等结构化加工
  → 按能力域、质量、难度、长度和来源分桶
  → 训练采样、损失归一化、污染审计与效果归因
```

只记录“用了多少图像”无法判断有效信息量。相同图像可以产生 caption、OCR、框点、比较、推理和工具轨迹；反过来，十亿低相关 web 图文对也可能比少量高质量细粒度数据更弱。

## 2. 完整数据能力矩阵

| 数据域 | 主要学习信号 | 常见失败 |
|---|---|---|
| 短/长 caption | 对象、属性、关系、描述风格 | 短 caption 丢细节；长 caption 幻觉 |
| Interleaved 图文 | 跨段落知识、多图语境、网页结构 | 图像与邻近文本弱相关 |
| OCR/文档/表格/公式 | 字符、布局、阅读顺序、结构 | OCR 错误被教师放大；扫描域偏差 |
| Chart/diagram/STEM | 数值、图形关系、多步推理 | 只学答案模板，不读坐标/图例 |
| Grounding/pointing | 框、点、区域指代和计数 | 坐标格式学会但视觉定位不准 |
| 多图 | 比较、变化、跨图引用 | image id 混淆、顺序投机 |
| 视频 | 事件、动作、时序、时间戳 | 只看关键帧/字幕，不建模时间 |
| GUI/网页/工具 | 元素定位、动作、环境反馈 | 静态截图高分但任务失败 |
| 视觉推理轨迹 | 图像证据到步骤与答案 | 教师长思维有错误或伪因果 |
| 纯文本 replay | 保持语言、知识、代码、数学 | 比例过高抑制视觉学习；过低造成遗忘 |
| 安全/拒答 | 隐私、成人、欺诈、越权工具 | 过拒或图像安全盲区 |

## 3. 大规模预训练语料提供什么

公开 web-scale 数据说明了规模上限，但不是拿来即用的金标准：

- [OBELICS](https://arxiv.org/abs/2306.16527) 从网页中构建大规模 interleaved 图文语料，强调文档级上下文和过滤。
- [MINT-1T](https://arxiv.org/abs/2406.11271) 扩展到 trillion-token、billions-of-images 级多模态 interleaved 数据，提供重要的规模参照。
- [MMC4](https://arxiv.org/abs/2304.06939) 研究网页内多图与文本对齐，而非只有独立 image-caption pair。
- [DataComp](https://arxiv.org/abs/2304.14108) 在固定训练框架下比较数据筛选策略，证明数据策展本身可以显著改变模型质量。

这些工作的共同启示是：**网页规模解决覆盖，不能独自解决细粒度 grounding、可靠 OCR、可验证推理和偏好质量。**

## 4. 数据处理流水线

### 4.1 来源与许可

每条样本必须有 source id、抓取/生成时间、许可状态、隐私/未成年人/生物识别风险、是否允许再分发。无法追溯来源的数据不应进入可交接配方。

### 4.2 基础清洗

- 解码完整性、尺寸、纵横比、极端压缩和水印；
- NSFW、暴力、隐私、恶意指令和文档机密；
- 语言识别、乱码、模板页、导航文本和广告；
- 图文相关性、caption 具体度、OCR 可读性；
- 图像内重复、跨来源重复、视频近重复。

过滤阈值不能只追求高 precision。过强的审美/CLIP 相似度过滤会删除图表、截图、低清文档和长尾文化内容，造成“漂亮照片强，工作场景弱”。应按能力域使用不同过滤器。

### 4.3 三层去重

1. **字节/URL/元数据**：便宜，先去完全重复。
2. **单模态近重复**：图像 perceptual hash/embedding，文本 MinHash/embedding。
3. **图文联合近重复**：检测同图改问法、同问换轻微裁剪、视频帧与图像测试集重叠。

训练去重和评测污染审计要使用相同 canonical id，并保留“为什么删除”的可解释记录。

### 4.4 Re-caption 与合成标注

教师模型可以把弱 alt-text 转成：

- 全局摘要；
- 对象、属性、相对位置的详细描述；
- OCR 转录和布局；
- 可验证问答；
- 框/点与区域描述；
- 视频事件和时间段；
- GUI 元素与动作轨迹。

但教师输出必须经过：

- 与 OCR/检测器/程序执行结果交叉核验；
- 多教师或多采样一致性；
- 置信度和拒绝率；
- 人工抽检；
- teacher model/version/prompt 可追溯；
- 防止测试集和特定 benchmark 风格泄漏。

Idefics3 的 Docmatix 流水线从文档生成 OCR 和问答，并展示高质量文档合成数据对 DocVQA 的明显价值：[Idefics3](https://arxiv.org/abs/2408.12637)。Molmo/PixMo 则强调人类详细描述与 pointing 数据的高信息密度：[Molmo and PixMo](https://arxiv.org/abs/2409.17146)。两者不矛盾：合成数据适合扩规模，人类数据适合校准质量和补教师盲点。

## 5. 质量评分不应只有一个标量

每个样本建议记录独立维度：

- 图文相关性；
- 视觉可读性；
- 信息密度/细粒度；
- 答案可验证性；
- 语言自然度；
- 多样性/新颖性；
- 安全与许可；
- 教师置信度；
- 能力域与难度；
- 与评测集近重复风险。

训练采样可以对这些维度建规则或学习一个 data scorer，但不能压成一个全局阈值后丢弃原始分数，否则无法解释模型退化来自哪个过滤维度。

## 6. 数据混合：比例不是通用常数

公开前沿配方差异很大：

- Qwen3-VL 在主要联合阶段持续混合视觉-语言与纯文本数据：[Qwen3-VL](https://arxiv.org/abs/2511.21631)。
- Kimi-VL 随训练推进提高多模态能力，同时保持原语言分布用于抗遗忘：[Kimi-VL](https://arxiv.org/abs/2504.07491)。
- InternVL3.5 披露的预训练与 SFT 文本/多模态比例并不相同：[InternVL3.5](https://arxiv.org/abs/2508.18265)。
- SmolVLM 的小模型研究发现，适量文本数据有帮助，但简单复用某些 LLM 指令数据会伤害图像/视频表现：[SmolVLM](https://arxiv.org/abs/2504.05299)。

所以正确问题不是“业界标准比例是多少”，而是：每增加一单位某类数据，对目标能力、文本回归和训练稳定性的边际收益是多少。

### 6.1 建议的层级采样

```text
先采能力域
  → 再采数据集/来源
      → 再采分辨率/长度/难度桶
          → 最后采样本
```

这样可以阻止超大数据集自动吞噬小而关键的 grounding、视频或安全数据。

数据集采样权重可从以下启发式起步，再用消融修正：

```text
p(dataset_i) ∝ quality_i × min(cap_i, size_i^α)
```

其中 `0 < α < 1` 用于抑制体量垄断，`cap` 限制重复 epoch；这是一种研究建议，不是来自论文的统一最优公式。

## 7. Token loss 的隐性数据配比

若按所有 response token 直接平均，一个 2,000-token 视频描述对优化器的权重可能是 20-token VQA 的百倍；若每样本等权，又可能让大量短答任务占优。

主要策略：

- per-token mean：稳定，但长样本支配；
- per-sample mean：样本等权，但短答权重很高；
- square-root normalization：权重随长度次线性增长；
- 分域/分任务显式权重：可控但需要调参；
- 每 batch 定额 token + category quota：在采样层控制。

Qwen3-VL 报告使用平方根归一化来平衡长短输出，InternVL3.5 也披露了相似的长度平衡思想；Molmo2 使用任务权重和长度相关缩放：[Qwen3-VL](https://arxiv.org/abs/2511.21631)、[InternVL3.5](https://arxiv.org/abs/2508.18265)、[Molmo2](https://arxiv.org/abs/2601.10611)。

**关键要求**：同时记录“抽到多少样本、输入多少 token、参与 loss 的输出 token、产生多少梯度贡献”。只看样本比例会误判真实训练权重。

## 8. Curriculum 设计

### 8.1 三条独立难度轴

课程不只是“分辨率越来越高”，而有三条轴：

1. **感知难度**：清晰单物体 → 小字/密集物体/低清扫描；
2. **序列难度**：单图短答 → 多图/多页/长视频；
3. **认知难度**：caption/抽取 → 多步推理/工具/开放式判断。

不应同时把三条轴拉满，否则难以归因训练失败。

### 8.2 推荐顺序

- 宽分布基础图文先形成覆盖；
- OCR/grounding 等专项能力尽早加入但逐步增权；
- 高分辨率在基本语义稳定后扩展；
- 多图、短视频、长视频按 token 长度渐进；
- 高质量可验证推理放到 cooldown/SFT/RL；
- 每次新阶段都 replay 旧能力数据。

### 8.3 原生早期联合路线的例外

Kimi K2.5 的固定预算研究支持更早地持续加入中等视觉比例，而非最后才大量注入视觉：[Kimi K2.5](https://arxiv.org/abs/2602.02276)。这提示“视觉越晚越好”并不成立；但其规模远大于普通开源小模型，仍需要在目标规模上做 scaling pilot。

## 9. 数据飞轮

最终系统应按错误类型回流数据，而非简单把所有线上对话加入训练：

```text
评测/线上失败
  → 聚类：看不清 / 不理解 / 不推理 / 不遵循 / 工具失败
  → 选择干预：预训练数据 / SFT / 偏好对 / RL 环境
  → 生成或人工标注
  → 去重、验证、进入候选池
  → 小规模因果验证
  → 才进入下一轮主训练
```

无图也答对的样本不适合拿来证明视觉学习；RL 奖励投机的失败也不能简单变成更多同类 CoT。错误必须路由到正确训练阶段。

## 10. 数据卡最低字段

每个数据集/版本至少记录：

- 名称、版本、来源、许可、时间范围；
- 图像/视频/文本数量，输入与目标 token；
- 语言、领域、分辨率、时长、质量和难度分布；
- 原始/人工/合成及教师版本；
- 过滤、去重、污染审计规则和删除比例；
- 采样权重、loss 权重、最大重复 epoch；
- 主要目标能力与已知偏差；
- 人工抽检结果；
- 训练过的 checkpoint 与边际效果。

没有这些字段，后续看到 benchmark 变化时无法把增益归因到数据。
